# RAG、用户记忆与访问边界核对

依据用户提供的三份设计材料，对照已有实现进行优化，不把材料中的框架或研究名词当成必须引入的依赖。

| 项目 | 原实现缺口 | 本次处理 |
|---|---|---|
| RAG 与用户记忆 | 提示词将旧 memory namespace 当知识证据；用户画像只写不读 | 分开证据与个性化槽位；只有文档命中才宣称知识库命中；认证模式不读取来源不明的旧共享 memory namespace |
| 长期身份 | 使用 conversationId 写用户记忆 | 使用服务端 tenant:user；同一用户可跨会话读取 |
| 工作记忆隔离 | 客户端会话 ID 可碰撞 | 认证模式下以租户、用户、当前角色/项目集合、选择项目和会话组成作用域；权限变化不复用原摘要 |
| 写入策略 | “不要”“必须”等临时要求会持久化 | 自动写入只处理明确长期请求；不抽取助手回答；手工 API 支持 preference/fact/episode/plan/procedure |
| 冲突与治理 | 只追加、无召回与删除 | 结构化 key 覆盖、版本号、有限历史、来源/置信度/时间/TTL；查看、修改、删除、清空、导出、暂停 |
| 租户 | 只有项目过滤 | 一个部署固定 RAG_TENANT_ID；Token 验签后核对租户；认证模式 Pinecone namespace 增加租户后缀；JDBC 数据库绑定租户防止误共用 |
| 权限 | 空项目白名单可能退化成全局查询；Token 权限更新不及时 | 空授权拒绝查询；每请求加载服务端当前角色项目；文档写入限 ADMIN/EDITOR，读取继续下推项目过滤 |
| 审计与输出 | 日志包含完整提问；记忆混入证据 | 日志记录身份、范围、命中 chunk ID 和记忆操作，不记录正文；生成只接触已过滤文档，个人记忆不作为引用证据 |

## 状态、工作记忆和长期记忆
当前应用是流式问答服务，没有 Agent 工具流程状态机。入库任务状态仍由生命周期仓储管理，不复制为个人画像；短期对话及压缩摘要属于 working memory。个人记忆属于独立结构化服务，RAG 文档保持版本及来源。不会为了凑齐四层概念增加未被调用的状态表。

偏好/流程短记忆直接按用户读取；事实、经历和计划按当前 query 的简单文本相关性筛选，最多注入6条。不是完整的语义事件召回引擎，不宣称实现向量 episodic memory 或多 Agent 共享记忆。共享制度仍走 RAG，未开放自由写共享画像。

## 个人记忆接口（必须开启认证）
- GET /api/memory：查看有效记忆和暂停状态。
- PUT /api/memory：{category,key,text}；相同 key 显式更新。
- GET /api/memory/history：有限旧版本。
- GET /api/memory/export：有效记录导出。
- DELETE /api/memory/{id}：同时删除当前与历史记录。
- DELETE /api/memory：清空当前和历史；保留暂停开关。
- PUT /api/memory/pause：{paused:true} 同时停止个性化读取及写入。

匿名演示不写个人记忆；API 不接收 owner 或 tenant。明显凭证及敏感标识拒绝入库，但简单规则不能保证识别所有隐私数据。用户主动输入不代表能覆盖系统指令或权限；权限始终由 Java 服务和检索预过滤执行。

## 部署与迁移
1. MySQL 部署依次执行 V1、V2、V3，V3 新建 rag_memory_profiles 及部署租户绑定表。旧 V2 记录错误使用了会话 ID，因此不自动迁移为用户画像。
2. 开启认证，配置强随机 Token secret 和固定 RAG_TENANT_ID；每个租户独立部署、独立生命周期数据库、独立原文存储目录/桶前缀。租户数据库绑定不一致会启动失败。
3. 认证模式 namespace 从原 namespace 切换到 namespace--tenant-ID，需要在新边界重新入库；不会读取旧共享 namespace。原 Token 不含租户字段，需重新登录。
4. JDBC 模式持久化用户状态；无 JDBC 的本地模式仅进程内保存，重启丢失。当前同步写入锁针对单 JVM，不宣称跨实例并发更新安全；集群部署需数据库行锁/CAS。
5. TTL 记录召回时失效，清理在写入时进行；历史最多100条，单用户有效记忆最多100条。显式删除清理历史；备份和日志的物理清理仍需运维保留策略。

## 尚不具备的企业能力
当前选择单租户部署，并未实现同一 JVM 内多租户路由、部门/段落级 ACL 管理、审批流、字段级 DLP 脱敏、合规级不可篡改审计、租户一键退租删除、跨区域迁移或多 Agent 共享状态。这些依赖组织权限与业务规则，不能仅凭材料虚构已具备。用户记忆还没有前端治理面板，本次提供受认证 API。

测试覆盖用户隔离、同键冲突覆盖、版本与删除、暂停、显式写入、匿名/敏感输入、会话权限作用域，以及现有认证与 RAG 回归。真实跨会话收益、写入精度和长期召回质量仍需业务数据评估。

补充边界：更新文档版本同时校验原文档和目标项目访问权限，避免通过改填 project 接管无权文档。短期记忆的内存降级副本同 Redis 一样采用7天过期。删除个人画像不会删除原会话记录或外部备份；需要清除历史对话时应按相应工作记忆和日志保留策略单独处理。
